# health-zoo

[English](README.md) | **Русский**

Одна страница, показывающая, здорова ли каждая железка в сети — серверы, NAS,
роутеры, камеры и меш-радио, — нарисованная тем деревом, которое они реально
образуют, с кнопкой установки накопившихся обновлений ОС.

Ничего не нужно ставить на хосты, нет базы данных, из зависимостей — только
`python3`. Хаб заходит на каждый хост по SSH, запускает там маленький shell-скрипт
и рисует то, что вернулось.



## Что показывает

Устройства сгруппированы по подсетям, а подсети вложены по реальной топологии:
аплинк-роутер → роутер площадки → сегмент камер за ним.

| Устройство | Собирается |
|---|---|
| Debian/Ubuntu | аптайм, нагрузка, ОЗУ/swap, диски, температуры, доступные обновления `apt` (security отдельно), требуется ли перезагрузка, сервисы, контейнеры, git-checkout'ы, мониторы ZoneMinder, а пока процессор загружен — кто именно его занимает |
| Synology DSM | версия DSM, тома, состояние RAID, давление на swap, температуры, установленные пакеты и версии, свежесть HyperBackup, камеры Surveillance Station |
| MikroTik RouterOS | версия, прошивка RouterBOARD (и нужна ли перезагрузка), CPU/ОЗУ/флеш, температура и напряжение, сервисы управления, установленные пакеты, состояние линков |
| OpenWrt | релиз, модель, занятость overlay/флеша, температуры, init-скрипты, интерфейсы |
| Meshtastic-ноды | аптайм, загрузка эфира, куча и файловая система, счётчик перезагрузок, RSSI Wi-Fi, батарея |
| Камеры | доступность и — что полезнее — говорит ли хост, который её пишет, что поток жив, и с каким fps |

**Сервисы обнаруживаются сами, их нигде не нужно перечислять.** Агенты
перебирают всё, что запущено на хосте; поставили что-то новое — оно само
появится на дашборде. В конфиге живёт только список хостов.

Версия каждого сервиса определяется через пакет, которому принадлежит его
unit-файл, поэтому «какой тут ZoneMinder» узнаётся без единой строчки знаний о
ZoneMinder.

## Обновление пакетов

У хостов с `updatable` появляется кнопка обновления, плюс общая **«Обновить
всё»**, которая проходит по ним по очереди и льёт лог прямо на страницу.

Машина, где крутится сам дашборд, обновляется **последней** — иначе она
перезапустит собственный сервис посреди прогона, — а её apt отвязан через
`setsid`, чтобы пережить этот перезапуск.

Обновляются только хосты семейства Debian. NAS и роутеры показываются, но не
трогаются: обновлять пакеты OpenWrt на месте — известный способ окирпичить
роутер, а обновления DSM требуют учётных данных, которых этот инструмент
намеренно не хранит.

## Что он вообще должен делать

[SPEC.ru.md](SPEC.ru.md) — требования, инварианты за ними и то, что сознательно
не делается. Обновляется вместе с кодом, а не после.

## Исключение находки

Любая система мониторинга рано или поздно показывает то, что известно, понято
и сегодня чиниться не будет. Оставить как есть — приучить себя не смотреть на
жёлтый дашборд; выключить проверку — забыть о ней совсем.

Способ принять известное состояние ровно один — этот. Нет флага в конфиге,
который тихо понижает находку: хост, который обычно выключен, всё равно горит
красным «не отвечает», пока кто-нибудь не напишет, почему так и задумано.

Исключение — ни то, ни другое. Проверка продолжает выполняться, её вердикт
по-прежнему виден, но она перестаёт красить хост и слать алерты, а рядом
написана причина. Причина обязательна — исключение без объяснения неотличимо
от проверки, которую никто не понял, — а необязательный срок возвращает
исключение на пересмотр.

Раздел **Исключения** показывает их по всему парку: возраст, остаток срока и
воспроизводится ли находка вообще. Последняя колонка и есть самая полезная:
исключение, которое уже ничего не скрывает, можно просто снять.

## Настройки

Пороги — это решения, а решения пересматривают, глядя на дашборд, а не правя
файл по ssh. Раздел **Настройки** их и правит: диски, память, температура,
загрузка эфира и качество Wi-Fi, свежесть бэкапа, тишина детекции, сроки
сертификатов. У каждого поля показано значение по умолчанию, а сохраняются
только те, что реально отличаются, — поэтому будущее изменение умолчания
по-прежнему дойдёт до всего, что не закреплено вручную.

У ролей свои переопределения (NAS с видеоархивом *должен* быть заполнен почти
под завязку) — они там же перечислены, а не спрятаны. У камер — по строке на
каждую: уличная камера, молчащая шесть часов, сломана, а гаражная, молчащая
двое суток, — это гараж, куда никто не заходил; одно общее число обязательно
сделает одну из них неверной.

**Автоматическая чистка** убирает пакеты, от которых уже ничего не зависит, —
вместе с обновлением, а не по отдельному расписанию. Включена по умолчанию и, в
отличие от перезагрузки, безопасна: apt сохраняет работающее ядро и всё, что
кому-то нужно. Она же расшивает застрявшие обновления — пакет, который
удерживался только из-за конфликта с ненужным, ставится на втором проходе.

Там же включается **автоматическая перезагрузка**: хосты, которые сами просят
перезагрузку, перезагружаются в заданном окне часов — по одному за цикл, не
чаще раза в сутки, никогда — хост с самим дашбордом и никогда — те, что внесены
в исключения. Перед каждой перезагрузкой уходит сообщение в Telegram. По
умолчанию выключено: дашборд, перезагружающий машины без спроса, — сюрприз, и
первый такой сюрприз случается посреди записи.

Хранится в `/var/lib/health-zoo/settings.json`, которым владеет сервис;
`/etc/health-zoo.json` остаётся описанием парка, написанным руками.

## Удаление сервиса

У каждого сервиса в карточке хоста есть кнопка удаления: она останавливает юнит,
убирает его из автозапуска и удаляет unit-файл. Юниты, принадлежащие пакету,
вместо этого останавливаются и маскируются — удалять их файлы бессмысленно,
следующее же обновление вернёт их обратно.

Юниты, снос которых отрезал бы доступ к хосту — `ssh`, `network`, `firewall`,
`systemd-*` и им подобные, — запрещены на сервере, а не просто спрятаны в
интерфейсе. Для подтверждения удаления нужно ввести имя сервиса.

### Секреты

Паролям не место в конфиге: он попадает в бэкапы, в вывод `cat` и на
расшаренный экран. Нужны два — токен бота Telegram и пароль контроллера
UniFi, — и оба хранятся по ссылке, а не значением:

```bash
printf %s 'сам-секрет' | sudo systemd-creds encrypt --name=telegram-token - \
    /etc/health-zoo.d/telegram-token.cred
```

`systemd-creds` шифрует ключом самой машины. Флаг `--with-key=host+tpm2`
дополнительно привязывает секрет к TPM: без него ключ хоста лежит в
`/var/lib/systemd/credential.secret` и уезжает с любым полным бэкапом, то есть
копия секрета вместе с копией бэкапа снова читается. (systemd отвечает
«TPM2 support is not installed», пока не установлен `libtss2-rc0` — единственная
библиотека, которую он подгружает для TPM; пропустить легко, потому что все
остальные libtss2 уже стоят.) systemd расшифровывает его при старте
в tmpfs-каталог, доступный только этому сервису. Конфиг же лишь называет
секрет:

```json
"telegram":         { "token_credential":    "telegram-token" },
"unifi_controller": { "password_credential": "unifi-password" }
```

Поддерживается и `<field>_file` — путь к файлу, если systemd-credentials
недоступны; простое `<field>` тоже продолжает работать, чтобы существующие
установки не сломались.

Честное ограничение: расшифрованное значение доступно тому пользователю, от
которого работает сервис. Это защищает конфиг, бэкапы и случайный взгляд
через плечо — но не того, кто уже вошёл под этим пользователем. Если это
важно, запускайте сервис под отдельной учётной записью.

### Точки доступа

В UniFi Network 10 убрали SSH-авторизацию устройств из standalone-приложения,
поэтому точки читаются через API контроллера — что и правильнее: один вход
отдаёт радио, клиентов, загрузку эфира и состояние прошивки всех точек сразу,
не трогая сами точки.

Учётная запись нужна с правами действия, а не View Only: чтение статистики и
перезагрузка радио идут через один и тот же endpoint, поэтому с read-only
кнопки перезагрузки и обновления прошивки работать не будут.

```json
"unifi_controller": {
  "url": "https://10.0.10.13:8443",
  "site": "default",
  "username": "health-zoo",
  "password": "…",
  "confirm_seconds": 60
}
```

Контроллер отвечает `rc: ok` на любое имя команды, в том числе на
несуществующее, — поэтому команда считается выполненной только после того, как
саму точку перечитали и увидели, что она сдвинулась. `confirm_seconds` — сколько
этого ждать, прежде чем ответ станет «не подтвердилось», а это не то же самое,
что «не удалось».

Роутер, который одновременно является точкой доступа, просто объявляет обе
роли: `"roles": ["router", "ap"]`.

### Перезагрузка

Перезагрузить можно любое устройство прямо с карточки — каждым тем способом,
который оно вообще предоставляет:

| Тип | Как |
|---|---|
| Debian/Ubuntu, OpenWrt | `shutdown -r`, отвязанный от ssh-сессии, которая умрёт вместе с хостом |
| RouterOS | `/system reboot` |
| Meshtastic | CLI `meshtastic` с хоста дашборда — нода говорит на protobuf, а не на shell |
| Камеры | ISAPI, запрос идёт **с того хоста, который её пишет**, учётные данные остаются на нём |
| Synology | `sudo reboot`, который DSM без пароля не выполнит (см. ниже) |

На время перезагрузки алерты по хосту молчат, чтобы плановый ребут не выглядел
как авария.

DSM не даёт passwordless sudo, а health-zoo намеренно не хранит пароль от DSM.
Чтобы разрешить перезагрузку — и заодно SMART, который тоже требует root, —
добавьте на NAS через `visudo` одну строку:

```
ваш-пользователь ALL=(root) NOPASSWD: /sbin/reboot, /usr/bin/smartctl
```

## Установка

```bash
curl -fsSL https://raw.githubusercontent.com/anton-vinogradov/health-zoo/main/install.sh | sudo bash
```

Ставится в `/opt/health-zoo`, создаётся systemd-юнит, генерируется SSH-ключ и
печатается его публичная часть. Дальше:

1. Разложить этот публичный ключ по всем хостам, которые нужно опрашивать.
2. Отредактировать `/etc/health-zoo.json` — список хостов, подсети и их родители.
3. `sudo systemctl restart health-zoo`

Дашборд слушает порт 8816. Повторный запуск установщика — это и есть обновление;
конфиг он не перезаписывает.

### Что нужно для доступа к разным типам хостов

| Хост | Нужно |
|---|---|
| Debian/Ubuntu | SSH-ключ; passwordless `sudo` — только для кнопки обновления и запросов к ZoneMinder |
| Synology | SSH-ключ. Работает полностью без привилегий: всё, что требует root, честно не показывается, а не угадывается |
| RouterOS | пользователь в группе `read` с импортированным ключом (`/user ssh-keys import`) |
| OpenWrt | ключ в `/etc/dropbear/authorized_keys` |
| Meshtastic | ничего — прошивка сама отдаёт `/json/report` по HTTP |
| Камеры | ничего — статус берётся у того, кто их пишет |

## Конфигурация

```json
{
  "poll_interval": 180,
  "ssh_key": "~/.ssh/id_health_zoo",
  "port": 8816,
  "subnets": [
    { "cidr": "0.0.0.0/0",     "name": "Интернет", "parent": null },
    { "cidr": "10.0.0.0/24",   "name": "Аплинк",   "parent": "0.0.0.0/0",   "router": "10.0.0.1" },
    { "cidr": "10.0.10.0/24",  "name": "Площадка", "parent": "10.0.0.0/24", "router": "10.0.10.1" }
  ],
  "hosts": [
    { "id": "box", "name": "box", "addr": "10.0.10.5", "user": "admin",
      "agent": "linux", "role": "server", "subnet": "10.0.10.0/24",
      "local": true, "updatable": true, "update_last": true }
  ]
}
```

`agent` — один из `linux`, `synology`, `routeros`, `openwrt`, `meshtastic` или
`none` (только ping и проверка портов). `role` (`server`, `nas`, `router`,
`camera`, `mesh`) задаёт иконку и группировку внутри подсети.

Все адреса лежат в конфиге; в репозитории нет ни одного.

## Как это устроено

```
hub.py      HTTP-сервер, цикл опроса, задания обновления и удаления
probe.py    опрос хостов, разбор отчётов, связывание камер с рекордерами
agents/*.sh передаются на хост через `ssh host sh -s`, печатают TSV-отчёт
```

Агенты написаны на POSIX shell и ничего не требуют на целевой машине — даже `jq`.
Они писались с оглядкой на цену: ранняя версия дёргала systemd на каждый юнит
отдельно и запускала `du` по архиву ZoneMinder, из-за чего опрос одного хоста на
Celeron N5105 занимал 44 секунды; батчинг тех же вызовов сократил это до двух.

Хосты опрашиваются параллельно, поэтому весь парк занимает примерно столько же,
сколько самый медленный из них. Браузеру всегда отдаётся последний завершённый
снимок.
